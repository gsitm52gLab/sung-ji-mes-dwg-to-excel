# 데크 발주서 자동 생성

건축 도면(dwg)에서 **데크 제작의뢰서(발주 엑셀)** 를 뽑아낸다. 지금까지 사람이
도면을 보며 손으로 만들던 발주서를, 도면에 그려진 부재 라벨에서 직접 산출한다.

```
arch-docs/dwg/*.dwg          ①ODAFileConverter          ②emit_areas.py
  (SHOP 도면 + DETAIL 도면)  ────────────────▶  *.dxf  ──────────────▶  발주 엑셀
                                (Docker)                              (층-구역별 1개)
```

- **SHOP 도면** — 부재가 어디에 몇 장 들어가는지. 구간 라벨·부재 수량이 여기 있다.
- **DETAIL 도면** — 데크 기호별 사양(타입·높이·피복·캠버). 일람표가 여기 있다.

---

## 준비 (최초 1회만)

### 1. Docker 이미지 빌드

dwg → dxf 변환은 ODAFileConverter(리눅스 전용)를 Docker로 돌린다.

```bash
docker build --platform linux/amd64 -t oda-converter convert-dwg-to-dxf/
```

Apple Silicon에서도 `--platform linux/amd64`로 에뮬레이션해 동작한다. 이미지
이름 `oda-converter`는 `convert-dwg-to-dxf.sh`가 그대로 참조하므로 바꾸지 말 것.

### 2. Python 의존성

Python 3.12 기준이다.

```bash
pip install -r requirements.txt
```

## 신규 dwg가 들어왔을 때

### ① dwg를 넣는다

`arch-docs/dwg/` 에 **SHOP 도면과 DETAIL 도면 두 개**를 넣는다. 폴더 안의 dwg는
전부 변환되므로, 쓰지 않을 도면은 넣지 않는 편이 낫다.

```bash
cp "260601_○○현장_DECK SHOP_....dwg"   arch-docs/dwg/
cp "260610_○○현장_DECK DETAIL.dwg"     arch-docs/dwg/
```

### ② dwg → dxf 변환

```bash
./convert-dwg-to-dxf/convert-dwg-to-dxf.sh
```

`arch-docs/dwg/` 의 dwg를 통째로 `convert-dwg-to-dxf/output/` 에 dxf로 낸다.
같은 이름에 확장자만 `.dxf`로 바뀐다. SHOP 도면은 100MB를 넘을 수 있고, 변환에
수 분이 걸린다.

### ③ config.yaml 을 새 도면에 맞춘다

**이 단계를 빠뜨리면 옛 도면으로 발주서가 나온다.** [config.yaml](config.yaml) 의
`emit.input` 두 줄을 ②가 만든 파일명으로 바꾼다.

```yaml
emit:
  input:
    shop_dxf:   "convert-dwg-to-dxf/output/260601_○○현장_DECK SHOP_....dxf"
    detail_dxf: "convert-dwg-to-dxf/output/260610_○○현장_DECK DETAIL.dxf"
    excel_glob: "arch-docs/excel/*.xlsm"     # 기존 발주서(대조용). 없으면 그대로 둔다
```

현장이 바뀌었다면 `emit.order_info` 도 함께 고친다. 제작의뢰서 머리말에 그대로
찍히는 값이고 도면에는 없다.

```yaml
  order_info:
    업체명:     "대우건설"
    현장명:     "식사푸르지오 파크센트"
    담당자:     "지에스아이티엠"
    하부받침대: "슬리퍼"
    포장유무:   "O"
    단부재유무: "O"
```

`요청코드`·`입고예정일`은 발주 건마다 달라서 **일부러 비워 둔다.** 생성된 엑셀을
열어 직접 채운다.

경로는 이 파일 위치(리포지토리 루트) 기준으로 풀리므로 어느 디렉토리에서
실행하든 같은 곳을 가리킨다.

### ④ 발주 엑셀 생성

```bash
cd convert-dxf-to-excel && python3 emit_areas.py
```

`convert-dxf-to-excel/output/area/` 에 **층-구역별로 파일 하나씩** 나온다.

```
B1F-B.xlsx   B1F-C.xlsx   B1F-가.xlsx   B1F-나.xlsx  …
지붕-가.xlsx  지붕-나.xlsx  지붕-다.xlsx  …
```

SHOP 도면을 처음 읽을 때 20초쯤 걸리고, 그 뒤로는 dxf 옆에 만들어 둔
`.cache.pkl` 을 쓴다. dwg를 새로 변환하면 캐시가 자동으로 무효화되므로 손댈 일이
없다.

## 결과 읽는 법

`emit_areas.py` 는 표를 하나 찍는다. 두 열만 보면 된다.

```
| 층   | 구역 | 구간 | 분할선 | 도면부재 | 도면의뢰행 | 장수 | 대조               | 파일         |
| B1F  | 사   |    9 |      6 |       32 |         18 |  364 | 14/17 행 일치      | B1F-사.xlsx  |
| B1F  | B    |    9 |      1 |       36 |         15 |  388 | 6/15 행 일치       | B1F-B.xlsx   |
| 지붕 | 마   |    5 |      2 |       19 |         11 |  208 | 발주서 없음 — 신규 | 지붕-마.xlsx |
```

**`대조`** — 같은 구역의 기존 발주서가 `arch-docs/excel/` 에 있으면 행별로 맞춰
본다. `발주서 없음 — 신규` 는 대조할 정답이 없다는 뜻이지 틀렸다는 뜻이 아니다.

**`분할선`** — 그 구역의 구간을 가르는 `@@@구간` 레이어 선의 개수. 구간 수에 비해
적으면 부재가 최근접 라벨로 흩어져 **구간별 장수를 믿기 어렵다.** 심하면 표 아래
경고가 따로 뜬다.

```
도면 경계 부족 — 구간 배정 근거가 없는 구역
    ⚠ B1F-B: 구간 9개에 분할선 1개. 구간별 장수를 믿기 어렵다.
    ⚠ B1F-가: 구간 3개에 분할선 0개. 구간별 장수를 믿기 어렵다.
```

이건 코드로 못 고친다. **도면에 구간 경계선을 그려 달라고 요청해야 한다.**
현 도면 실측으로는 이렇게 갈린다.

| 구역 | 분할선/구간 | 일치 |
|---|---|---|
| 마 | 9/7 | 8/9 (89%) |
| 바 | 3/4 | 5/5 (100%) |
| 사 | 6/9 | 14/17 (82%) |
| 나 | 1/4 | 5/6 (83%) |
| **B** | **1/9** | **6/15 (40%)** |

분할선이 구간 수의 절반을 넘는 구역은 합쳐서 **27/33 (82%)** 맞는다. 다만 이
지표가 모든 걸 설명하지는 않는다 — C 구역은 1/2(0.50)인데 0/2다. 그쪽은 경계가
아니라 SLAB 표기(도면 `DS3s` ↔ 엑셀 `DS3`)가 어긋난 별개 문제다.

## 생성 파일의 구조

발주서 원본과 같은 5시트다. 마지막 `도면대조` 만 이 파이프라인이 덧붙인다.

| 시트 | 내용 |
|---|---|
| `제작의뢰서` | 발주서 본문. 15행부터 데이터, 그 위 14행은 머리말 |
| `Sheet1` | 부재 한 줄씩. 17행부터, 머리말 없음 |
| `RECHECK` | 제작의뢰서를 비추는 생산측 점검표. 타입·길이·수량 체크 칸은 비어 있다 |
| `일람표` | 데크 기호별 사양. 제작의뢰서의 `VLOOKUP` 이 참조한다 |
| `도면대조` | **표준 아님.** 기존 발주서와의 행별 대조 + 부재가 도면 어디서 왔는지 추적 |

`도면대조` 의 `[추적]` 은 제작의뢰서 한 행이 도면의 어느 부재(좌표·도면NO·장수·
잔여)에서 나왔는지 적는다. **기존 발주서가 없는 구역에서 결과를 손으로 검산할
유일한 단서다.**

## 검증용 스크립트

발주서를 만드는 건 `emit_areas.py` 하나면 되고, 나머지는 **기존 발주서가 있을 때
얼마나 맞는지 확인하는 용도**다. 전부 `convert-dxf-to-excel/` 에서 실행한다.

| 스크립트 | 무엇을 대조하나 | 출력 |
|---|---|---|
| `emit_order.py` | 제작의뢰서(구간 합계) | `output/zone/제작의뢰서_*.xlsx` |
| `emit_sheet1.py` | Sheet1(부재 단위) | `output/zone/Sheet1_*.xlsx` |
| `emit_by_zone.py` | 일람표(사양) | `output/zone/일람표_*.xlsx`, `구역별_대조.csv` |
| `poc_deckorder.py` | 부재 배정 전략 7종 비교 | `output/poc/제작의뢰서_PoC.xlsx` |

`emit_by_zone.py` 는 DETAIL 도면의 일람표를 검사한다. **여기서 불일치가 나오면
사양 자체가 어긋난 것이라 먼저 잡아야 한다.**

## 알려진 한계

**구간 배정** — 부재를 어느 구간에 넣을지는 도면의 분할선과 구획 폴리곤으로
정한다. 둘 다 없는 구역은 최근접 라벨로 흩어져 구간별 장수가 틀어진다. 현재
제작의뢰서 일치율은 54행 중 38행(70%)이고, 경계가 그려진 구역만 보면 82%다.
남은 오차의 대부분이 B 구역 한 곳(9구간에 분할선 1개)에서 나온다.

**길이 재배분** — 기존 발주서 자체가 `Sheet1` 과 `제작의뢰서` 에서 길이를 다르게
적는 경우가 있다(예: Sheet1 `3410:26` ↔ 제작의뢰서 `3310:13 + 3410:13`). 합계는
같은데 배분이 다르다. 도면에는 그 근거가 없어 재현할 수 없다.

**Sheet1 의 면적 3열** — `V`·`W`·`X`(실투입물량 등)는 원본이 수식 없이 값만 박아
놓아 규칙을 알 수 없다. **비워서 낸다.** 짐작으로 채우면 물량이 틀어진다.

**층 구분** — SHOP 도면 한 장에 층별 평면도가 가로로 나란히 놓이고 구간 이름이
층 사이에서 겹친다(지하1층 `마-1` 과 지붕 `마-1`). `AA-TEXT` 레이어의 평면도
제목을 기준점 삼아 가른다. 제목이 없거나 다른 레이어에 있으면 실패한다.

## 문제 해결

**`AA-TEXT 레이어에서 평면도 제목을 찾지 못했습니다`**
SHOP 도면에 `지하1층 주차장 구조평면도` 같은 평면도 제목이 없거나 다른 레이어에
있다. 도면 작성 규칙 확인이 필요하다.

**`B1F 층을 도면에서 찾지 못했습니다`** / **`도면에 B1F 층이 없습니다`**
기존 발주서 파일명의 층 표기(`B1F-사`)와 도면의 평면도 제목이 안 맞는다. 있는
층 목록이 오류 메시지에 함께 나오니 그것과 맞춘다. 층 이름은 평면도 제목에서
뽑는다 — `지하1층…` → `B1F`, `지붕…` → `지붕`.

**`대조` 가 전 구역 `발주서 없음 — 신규`**
`emit.input.excel_glob` 이 기존 발주서를 못 찾고 있다. 경로와 확장자(`.xlsm`)를
확인한다. 신규 현장이라 정말 없는 것이라면 정상이다.

**엑셀 잠금 파일**
`~$이름.xlsm` 은 자동으로 걸러지므로 발주서를 열어 둔 채 실행해도 된다. 다만
편집 중인 내용은 저장 전까지 반영되지 않는다.

**변환 결과가 옛 도면 그대로**
③에서 `config.yaml` 의 `shop_dxf`·`detail_dxf` 를 안 고쳤을 가능성이 가장 크다.
실행 시 출력되는 경로를 확인한다.
